How Vendo turns a business's API into an OKX AI listing

Vendo sits between AI agents and a business's existing service. OKX provides the payment rails and the marketplace; Vendo makes them usable for a normal business.

The request path

1. An agent finds the listing on OKX AIThe listing points to a Vendo-hosted endpoint, e.g. https://vendo.app/northgate-bakery/v1/catering-quote.
↓
2. Vendo answers with a payment requestBuilt with the OKX Payment SDK: HTTP 402 with a PAYMENT-REQUIRED header, priced in USDT0 on X Layer, paid to the listing owner's wallet.
↓
3. The agent pays and retriesIts Agentic Wallet signs the payment; the OKX facilitator verifies and settles it onchain.
↓
4. Vendo forwards the call to the businessVendo adds the business's API key from encrypted storage and calls their real API (or submits their verified website form). Buyers never see the key.
↓
5. Result returned, sale recordedThe agent gets the response. Vendo records the sale with its settlement proof for the books, proof page and treasury.

How a business connects

Has an APIPaste an OpenAPI link or add routes by hand. Vendo proposes which endpoints to sell, hides ones that look private, and stores any API key encrypted.
No APIPoint Vendo at a booking or quote form on the business's own website. Ownership is proven with a meta tag or a file on the domain before anything goes live.

Who owns the listing and the revenue

On OKX AI, whoever lists a service keeps the revenue it generates. Vendo supports both ways of working:

What stays safe

  • Credentials: upstream API keys are encrypted at rest and never returned by any Vendo API.
  • Consent: nothing is listed without the owner's approval; website forms need domain verification.
  • Network safety: Vendo only calls public https addresses, with timeouts and size limits.
  • Money: in self-listed stores Vendo never touches funds. The optional vault lets automation keep a buffer and pay approved bills, but never pay unapproved addresses or raise limits.

OKX building blocks used

OKX AI (A2MCP listings), OKX Payment SDK (x402), Agentic Wallet (identity and payments), Onchain OS (registration), X Layer (USDT0 settlement and the vault contract).
